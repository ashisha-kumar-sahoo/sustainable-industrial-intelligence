# Facility configuration and demo assumptions

## Facility profiles

The same dashboard and analytics architecture supports two configuration profiles:

- **Industrial Estate** — energy, water, waste, environment, traffic, equipment and safety.
- **Hospital** — energy, water, waste, environment, equipment and safety.

Select the profile from the dashboard sidebar under **Facility profile**. The hospital profile is a configuration demonstration; the seeded PostgreSQL dataset remains industrial-estate data and must not be presented as hospital measurements.

## Data source

PostgreSQL is the source of truth when `DATABASE_URL` / `DB_*` settings are configured. Synthetic data is used only as an explicitly labelled fallback when PostgreSQL is unavailable.

## AI/ML evidence

- Energy and water anomaly pipelines use the PostgreSQL readings and deterministic deviation from the observed baseline.
- Waste overflow uses physical `fill_level_percent` and `fill_rate_percent_per_hour` telemetry.
- Forecast evidence in the dashboard uses a one-step persistence backtest with MAE/RMSE.
- The prototype does not contain ground-truth anomaly labels, so precision/recall are not claimed.

## Limitations

- Synthetic/sensor-style readings are demonstration data, not official industrial measurements.
- Waste telemetry added to new readings is simulated; existing historical rows remain unchanged unless explicitly backfilled and labelled as estimated.
- The local Qwen model explains evidence generated by PostgreSQL/rules; it is not the source of truth.
